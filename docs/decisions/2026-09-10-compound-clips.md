# B′5 Phase 6B — 컴파운드 만들기·해제와 보존 클립 복구

작성 2026-09-10. Codex 세션이 사용량 한도로 멈춰 Claude가 직접 구현했다.

## 왜 이 배치가 필요했나

Phase 0~6A 로 중첩 시퀀스가 저장되고, 순환에서 살아남고, 화면에 그려지고,
소리가 나고, 탭으로 열린다. 그런데 **사용자가 만들 방법이 없었다.**
문서에 이미 있는 시퀀스 클립만 동작했다. 다섯 단계의 투자 전체가 도달 불가능했다.

## 컴파운드 만들기 — 내린 판단

- **간격을 보존한다.** 선택한 클립 사이의 빈 시간을 그대로 유지한다.
  앞으로 당겨 붙이면 사용자가 보던 타이밍이 조용히 바뀐다.
- **빈 트랙은 물려주지 않는다.** 선택된 클립이 실제로 놓인 트랙만 자식이 된다.
- **시퀀스 클립은 가장 먼저 시작하는 클립의 트랙에 놓인다.** 사용자의 시선이 그곳에 있다.
- **삽입 게이트를 통과한다.** Phase 2 의 `sequenceEditReason` 을 그대로 쓴다.
  선택 안에 이미 시퀀스가 있으면 깊이가 한 단 늘어나므로 상한을 넘길 수 있다.
- **이름은 타임라인이 아니라 클립에 붙인다.** `Timeline` 에는 이름 필드가 없고,
  추가하면 model + zod + CRDT 를 건드린다. 그건 6C 가 다룰 표면이다.
  `ClipBase.label` 이 이미 있고 사용자가 보는 것도 클립이다.

## 컴파운드 풀기 — 내린 판단

**푸는 것이 화면을 바꾸면 안 된다.** 이 한 문장이 나머지를 결정했다.

- 부모 클립이 자식의 일부만 보여주고 있었다면 **푼 결과도 그 부분만**이다.
  잘려 있던 구간이 되살아나면 렌더 결과가 달라진다.
  대신 몇 개가 빠졌는지 알린다. 조용히 잃는 것이 가장 나쁘다.
- 머리가 잘려 있었으면 **소스 안으로 그만큼 들어간다.** 그러지 않으면
  플레이헤드 아래 프레임이 바뀐다.
- **속도 램프가 걸린 컴파운드는 풀지 않는다.** 램프는 시간을 비선형으로 매핑하는데
  클립별 속도 값으로는 표현할 수 없다. 억지로 풀면 재생 결과가 달라지므로
  거부하고 이유를 설명한다.
- 다른 클립이 같은 자식을 아직 쓰고 있으면 자식 타임라인을 지우지 않는다.

## 보존 클립 복구 (계획서 29번)

병합으로 트랙 위치를 잃은 클립은 문서에 보존되지만 타임라인에도 영상에도 없다.
지금까지 사용자가 되살리거나 버릴 방법이 없어 **개수 알림이 세션마다 다시 떴다.**

- 되살리기는 다른 클립과 **같은 삽입 게이트**를 통과한다. 순환을 만들 수 없다.
- 폐기는 되돌릴 수 없으므로 확인을 받는다. 실행 취소로도 복구되지 않는다고 명시한다.
- 마지막 하나를 처리하면 필드 자체가 사라져 알림이 더는 뜨지 않는다.

## 컨텍스트 메뉴 대신 명령 팔레트로 검증한 이유

Radix 컨텍스트 메뉴는 Playwright 에서 항목이 활성화되지 않는다.
**기존 항목("Duplicate")으로 확인했고 동일하게 동작하지 않았다.**
이 저장소의 어떤 브라우저 검증도 컨텍스트 메뉴를 쓰지 않았던 이유다.

하네스와 싸우는 대신 두 명령을 **명령 팔레트에 노출**했다.
제품 관점에서도 이쪽이 낫다 — 키보드 중심 사용자가 도달할 수 있어야 하고,
전문 편집기는 이런 명령을 팔레트에 둔다.
컨텍스트 메뉴 경로는 단위·스토어 테스트가 덮는다.

## 부수적으로 고친 것

우클릭이 다중 선택을 단일로 되돌리고 있었다. 선택 안의 클립을 우클릭하면
선택이 유지되도록 고쳤다. 그러지 않으면 컴파운드 명령이 커서 아래 클립 하나만 본다.

시퀀스 클립을 영상 트랙에 놓을 수 있게 했다. 이전에는 "미디어가 아님"으로 분류돼
텍스트·오버레이 트랙에만 놓였다. 컴파운드는 그림과 소리를 함께 담는다.

## 검증

코어 8, 스토어 5, 보존 복구 4, 브라우저 여정 4(ko/en 각 2).
여정은 선택 → 묶기 → 탭으로 자식 열기 → 부모 복귀 → 풀기 → 원래 두 클립 복원까지 돈다.
**컴파운드가 없으면 탭 줄이 보이지 않는다**는 것을 각 여정의 첫 단언으로 고정했다.
`pnpm gate` 9/9 PASS.
