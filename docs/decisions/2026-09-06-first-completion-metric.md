# C3 — 로컬 첫 완성률 (2026-09-06)

기본 꺼짐, 명시적 옵트인. 앱의 fetch/beacon/원격 SDK/계정 없음. 이 브라우저 프로필 또는 Mac의 IndexedDB에만 보관하며 JSON 다운로드만 사용자가 시작한다. 파일명·경로·미디어·명령 라벨·오류 메시지·자유 텍스트는 수집하지 않는다. 프로젝트 식별자는 SHA-256 해시로만 저장한다. 원래 ID도 DB/JSON에 기록하지 않는다.

## 모집단과 단계

- 시작: 측정 중 새 프로젝트 생성. C1 선택 종류는 organize(가져오기), manual, guided 별도 이벤트로 기록한다.
- 활성화 당시 또는 기존 프로젝트를 열 때 관찰을 시작한 프로젝트는 baseline이다. 자산/클립이 이미 있으면 baseline 단계로 표시한다.
- 단계: 시작 → 첫 자산 등록 성공 → 첫 클립 배치 → 첫 내보내기 시작 → 첫 내보내기 성공. 완성은 자산 ≥1, 클립 ≥1인 내보내기의 실제 저장/다운로드 성공이다. 저장 대화상자 취소는 성공이 아니다. 여러 프리셋 중 하나라도 성공하면 완성이다.
- 첫 완성률 = 측정 중 생성되고 첫 가져오기까지 도달한 프로젝트 중 완성한 프로젝트 / 측정 중 생성되고 첫 가져오기까지 도달한 프로젝트. 0개 분모는 비율 없음이다.
- baseline 프로젝트는 분자·분모·단계별 도달 수·소요 시간에서 제외하고 별도로 표시한다. 라벨은 “기록이 켜진 뒤 만든 프로젝트 기준”. 사람의 최초 사용, 설명 없이 완성, 도움 유무를 추론하지 않는다.
- 단계별 소요 시간은 직전 단계에서 해당 단계까지의 시간 중앙값(ms); 해당 두 단계가 순서대로 있는 프로젝트만 포함한다. 비활성 시간/앱 종료 시간도 포함하는 벽시계 시간이므로 숙련도 자체가 아니다.
- undo는 history의 future 증가, 명령은 새 history 항목(redo 제외)을 센다. 드래그 합치기·원격 변경·유지보수는 명령 수와 일치하지 않을 수 있는 근사치다.

## 복구와 한계

복구 종류는 누락 재연결, 스냅샷 복원, 저장 충돌 해결, 가져오기 재시도이다. 결과는 success/abandoned/pending이다. 포기는 명시적 취소/닫기만 기록한다. 숫자 episode 식별자로 pending과 최종 결과를 연결하며 에피소드당 최종 결과는 한 번만 기록한다. 재연결 20개 중 19개 성공 후 닫으면 abandoned 1회, assets=20·resolved=19이다. 전체 성공은 success 1회이며 중복 취소/닫기는 무시한다. 실패는 pending을 유지하며 종료/새로고침만으로 포기로 추측하지 않는다. 결과 시점에 해당 복구의 명시적 C2 test id(재연결은 media-missing-hint)가 화면에 표시되는지만 불리언으로 기록하며 도움을 읽었는지는 알 수 없다. 해당 복구 UI가 없는 기준 브랜치의 종류는 0으로 표시한다.

## 보관과 실패

행은 append-only이며 수정하지 않는다. command/undo는 메모리 카운터로 합산하고 5분 간격·리포트 열기·페이지 숨김·언마운트 때 activity 증분(commands, undos) 한 행으로 기록한다. 프로젝트당 1,000행, 전체 5,000행을 넘으면 activity 및 비단계 행만 오래된 순으로 정리한다. start/path/import/clip/export*/recovery는 절대 정리하지 않으며 보호 행만 상한을 넘으면 상한은 소프트 제한이다. 과거 버전에서 시작 행이 이미 사라진 프로젝트는 불완전 기록으로 별도 표시한다. 지표는 보존된 로컬 기록에 한정되며 장기 누적 통계가 아니다. 비활성화는 구독과 대기 큐를 제거하고 기존 기록을 유지한다. 모두 삭제는 대기 작업까지 비우고 기존 세션을 baseline으로 다시 시작한다. 로깅 오류는 편집·저장·내보내기로 전파하지 않는다. 언마운트·pagehide·visibilitychange(hidden)는 해시 대기 후 flush를 시작하며 비동기 쓰기의 종료 전 완료는 보장할 수 없다. discard는 옵트아웃·삭제에만 적용한다. 내보내기는 한 프리셋 큐당 최종 결과 한 번이며 첫 저장 성공 시 즉시 success를 한 번 기록하고, 모두 저장 취소면 failure(cancelled=true)다. 짧은 큐 작업을 idle callback(대체 타이머)으로 flush하며 DB 작업은 비동기다.
