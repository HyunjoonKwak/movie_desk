# 원본 모으기 — 3단계

작성 2026-09-10. `2026-09-08-library-model.md` 가 승인한 모으기의 구현.

## 순서가 곧 안전장치다

    복사 → 검증 → 참조 교체 → 원본 보존

이동으로 구현하면 중간 실패 시 원본도 사본도 온전하지 않은 상태가 생긴다.
그래서 **절대 이동하지 않는다.**

검증은 양쪽의 full hash 비교다. quick hash 는 크기와 앞뒤 조각만 보므로
가운데가 깨진 사본을 통과시킬 수 있다. 모으기는 그 결과로 참조를 옮기는
작업이라 여기서만큼은 전체를 읽는다.

## 임시 이름으로 먼저 복사한다

`<target>.partial` 로 복사한 뒤 검증에 성공해야 진짜 이름으로 rename 한다.
중간에 끊기거나 검증에 실패하면 임시 파일을 지운다.
이렇게 하지 않으면 **잘린 파일이 진짜 이름을 달고 남아** 나중에 정상 파일로 오인된다.

## 파괴적 실수를 막는 지점

- **자기 자신에게 복사하지 않는다.** 원본이 이미 목적지에 있으면 건너뛴다.
  `copyFile` 로 같은 경로를 쓰면 파일이 잘린다.
- **덮어쓰지 않는다.** 같은 이름이 있으면 `이름 1.mp4` 처럼 번호를 붙인다.
  기존 파일이 무엇이든 손대지 않는다.
- **원본이 오프라인이면 건너뛴다.** 추측해서 다른 파일을 옮기지 않는다.
- **하나가 실패해도 나머지를 계속한다.** 그리고 양쪽 결과를 모두 보고한다.
- **원본은 지우지 않는다.** 삭제는 검증이 끝난 뒤 사용자가 따로 결정하는 별개 행동이다.

## 목적지는 네이티브 선택기로 고른다

렌더러가 경로를 지정하지 않는다. 메인이 폴더 선택기를 띄우고 사용자가 고른 곳만 쓴다.
지금까지 지켜온 "절대경로는 페이지로 넘어가지 않는다" 경계와 같은 이유다.
선택을 취소하면 성공처럼 보이지 않고 `CANCELLED` 로 끝난다.

## 위치 등록을 가져오기와 공유한다

모으기는 복사한 목적지에 대한 root 가 필요하다. 참조 가져오기가 이미 그 절차를
갖고 있으므로 `registerRootForFile` 로 꺼내 공유했다. 복제하면 두 경로가 갈라진다.

## 구현 중 잡은 결함

검증에 쓴 해시 변수가 `try` 블록 안에 갇혀 참조 갱신 시점에 접근할 수 없었다.
테스트가 잡았다. 오류 코드가 없는 예외로 뭉뚱그려져 있어 원인이 보이지 않았고,
디버그 필드를 잠깐 넣어 메시지를 확인한 뒤 제거했다.
이게 없었다면 **모으기가 항상 실패하되 이유를 알 수 없는** 상태로 나갔을 것이다.

## 아직 없는 것

사용자가 이 기능을 실행할 화면. 로직과 통로까지만 있다.
참조 위치 패널에 붙이는 것이 자연스럽고, "위치별로 모으기"와
"프로젝트가 쓰는 것만 모으기" 중 무엇을 먼저 노출할지는 화면을 만들 때 정한다.

**사용 구간만 잘라 모으는 방식은 여전히 범위 밖이다.** 여유분을 버리므로 나중에
트림을 늘릴 수 없고 되돌릴 수 없다. 넣더라도 명시적 opt-in 이어야 한다.
