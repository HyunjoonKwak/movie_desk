# 제자리 참조 가져오기 — 1단계

작성 2026-09-10. `2026-09-08-library-model.md` 가 승인한 방향의 첫 구현.

## 무엇이 바뀌었나

데스크톱에서 영상·이미지·오디오 원본을 **복사하지 않고 있던 자리에 등록**한다.
카탈로그가 위치를 배우고, 바이트는 사용자가 둔 곳에 그대로 남는다.

## 새 개념이 아니라 기존 경로를 넓힌 것

HEIC 가져오기(A4)가 이미 이 방식으로 동작하고 있었다. 볼륨을 해석해 root 를 등록하고,
지문을 만들고, 같은 위치의 기존 자산이 있으면 재사용한다.
`reference-import.cjs` 는 그 절차를 그대로 따르되 대상 형식만 넓힌다.
그래서 새로 만든 위험은 형식 매핑과 분기뿐이다.

## 계층

| 계층 | 역할 |
| --- | --- |
| `apps/desktop/src/reference-import.cjs` | 검증 → 볼륨 해석 → root 등록 → 자산 upsert |
| `main.cjs` IPC | `movie-desk:media-import-file` |
| `preload.cjs` | 격리된 곳에서 경로 해석 후 main 으로 직송 |
| `desktop-reference-import.ts` | 응답 검증, 절대경로 유출 거부 |
| `import-batch.ts` | HEIC / 참조 / 복사 세 갈래 |

## 지킨 것

**원본에 쓰지 않는다.** 테스트가 가져오기 전후의 크기와 수정 시각이 같고
폴더에 새 파일이 생기지 않았음을 확인한다. 이것이 이 배치의 핵심 단언이다.

**절대경로는 페이지로 넘어가지 않는다.** main 은 `lastKnownAbsolutePath` 를
복구 힌트로 갖지만 응답에서 제거한다. 렌더러 스키마는 그 필드를 `z.undefined()` 로
선언해 **값이 오면 거부한다.** 검사로 거르는 것이 아니라 스키마가 막는다.
테스트는 직렬화한 응답 전체에 디렉터리 이름이 등장하지 않는 것까지 확인한다.

**같은 파일을 다시 가져오면 id 가 유지된다.** 기존 프로젝트의 참조가 끊기지 않는다.

**탐색 실패가 배치를 멈추지 않는다.** 컨테이너를 못 읽어도 가져오기는 성공하고
렌더러가 디코딩한다. 파일 하나 때문에 수백 개 배치가 죽으면 안 된다.

**웹은 그대로 복사한다.** 브라우저는 한 번 건네받은 파일을 다시 열 안정적인 방법이
없다. 참조 브리지가 없으면 분기가 자동으로 복사로 떨어진다.
D1 이 `apps/web` 을 개발 미리보기로 규정한 것과 일치한다.

## 하지 않은 것

기존에 복사로 들어온 자산을 참조로 바꾸는 마이그레이션은 없다.
그건 사용자가 원본이 어디 있는지 지목해야 하는 작업이고,
2단계(참조 위치 화면)와 3단계(모으기)가 그 수단을 만든 뒤에 다룬다.

## 다음

2단계는 **참조 위치를 보여주는 화면**이다. 사용자가 "내 원본이 어디 있지"라고
물었을 때 답이 화면에 있어야 한다. root 에 이름을 붙이고 오프라인 상태를 보여준다.
이번 배치가 그 데이터를 만들었으므로 이제 보여줄 것이 생겼다.

3단계는 **모으기**다. 복사 → 검증 → 참조 교체 → 원본 보존 순서이며
`2026-09-08-library-model.md` 에 절차가 기록돼 있다.
