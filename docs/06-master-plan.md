## 계획을 세우는 규칙

1. 새 기능은 "편집을 모르는 내가 다음에 막히는 지점"에서만 나온다. 로드맵보다
   도그푸딩 기록이 우선이다.
2. 계층 순서는 정체성 > 기반 > 부가다.
3. phase의 완료 기준은 늘 같다. **실제 촬영본으로 한 편을 처음부터 끝까지 만들어
   가족에게 보냈는가.**
4. 크기 표기: S = 반나절~하루, M = 2~4일, L = 1~2주.

## Phase 0 — 정리하고 내보내기 (S~M)

목표: 지금 상태를 main과 릴리스로 고정한다.

- `feat/identity`를 main에 병합하고 푸시한다.
- CI 복구: 루트 `pnpm.overrides`의 postcss·nanoid를 OSV가 고쳐진 것으로 보는
  버전으로 올리고 `pnpm audit:prod`가 통과하는지 확인한다.
- v0.4.0 "Movie Desk" 릴리스: desktop 버전 0.4.0, 태그, dmg 확인. 설치 배경
  PNG가 SVG와 같은 이름을 보여 주는지 본다.
- 상표 1차 조사 30분(KIPRIS, USPTO 검색)과 결과를 identity 문서에 적는다.
- 포맷 기준 결정: biome를 전면 적용하는 형식 전용 커밋 1개, 또는 format을
  게이트에서 빼는 것으로 명시.

완료 기준: main CI 녹색, Releases에 v0.4.0.

## Phase 1 — 내 영상으로 한 편 끝내기 (도그푸딩, M)

목표: 로드맵을 추측이 아니라 실제 막힘으로 채운다.

- 실제 세트 1개를 고른다. 최근 여행 또는 아이 영상과 사진, 아이폰 원본 그대로
  (HEIC·HEVC·.mov 포함) 50~200개.
- 여정 6단계를 그대로 밟는다. 던진다 → 정리된다 → 리포트 → 초안 → 채택·제외 →
  마무리 → 내보내기 → 가족에게 전송.
- 막힌 지점, 이해 안 된 문구, 기다린 시간을 `docs/dogfood/2026-09-xx.md`에 적는다.
  이 목록이 Phase 2~4의 순서를 정한다.

검증 전 예상 막힘: HEIC 가져오기 실패, 4K 분석 대기, 리포트 용어, 초안 컷이 왜
그렇게 잘렸는지, 내보낸 파일을 어디로 어떻게 보낼지.

완료 기준: 완성본 1편 전송, 막힘 목록 1개.

## Phase 2 — 아이폰·카메라 원본 그대로 받기 (M~L)

- HEIC/HEIF 디코드: 로컬 wasm 디코더(libheif 계열)로 썸네일·프레임 추출, EXIF 유지.
- HEVC(H.265) 재생·분석·내보내기 경로 검증. WebCodecs 지원 여부에 따른 안내.
- .mov 컨테이너, Live Photo(정지 프레임만), 세로 영상 회전 메타, 폴더 드래그
  재귀와 카메라 DCIM 구조.
- 가져오기 실패 시 "왜, 어떻게" 안내. 지금은 토스트 한 줄뿐이다.

완료 기준: 아이폰 기본 설정 촬영본이 변환 없이 전부 들어온다.

## Phase 3 — 초안 품질 (정체성의 핵심, L)

- 리포트 언어를 비전문가 기준으로 다시 쓴다. 수치보다 "무엇이 있고 무엇을 만들
  수 있는지".
- 컷 이유 표시 강화: 채택·탈락 카드에 한 줄 이유(얼굴, 흔들림, 골든아워, 중복).
- 성장 기록 모드: 인물 중심 세트로 검수, 얼굴 신호 가중 조정.
- 사진+영상 혼합 세트, 음악 없는 모드의 리듬.
- 분석 속도: 장면 감지·모션 트래킹을 WebCodecs 디코더 공유로 옮긴다
  (`04-honest-gap-analysis.md` 항목 2). 대용량 세트의 진행률과 중단.
- 재조립 시 이전 맵 자산이 라이브러리에 남는 문제 정리.

완료 기준: 도그푸딩 2회차에서 초안을 "손볼 만하다"고 느낀다.

## Phase 4 — 마무리와 공유 (M)

- 제목 카드·챕터 카드 템플릿(여행/성장) 2~3종, 한글 폰트.
- 자막: Whisper 한국어 모델 옵션 검토. 지금은 영어 tiny 모델이다.
- 공유용 내보내기 프리셋: 가족 메신저(용량 우선), 유튜브, TV·아이패드.
  내보내기 뒤 "어디로 보낼지" 단계.
- 프로젝트 백업·복원 안내. JSON 내보내기는 이미 있다.

완료 기준: 내보내기 후 다른 도구 없이 가족에게 보낸다.

## Phase 5 — 신뢰성·성능 기반 (M, 다른 phase와 병행)

- e2e에 자동 편집 여정 1개(ffmpeg 태그 클립으로 재현 가능)와 내보내기 스모크.
- mp4-muxer를 후속 라이브러리로 교체.
- 메인 스레드 렌더 분리·WebGPU는 실제 끊김이 확인될 때만.
- knip 정리, 버전 단일화(root/web/core를 desktop과 맞춤).

완료 기준: CI가 정체성 기능을 지킨다.

## Phase 6 — 공개와 확장 (관심사가 생기면)

- 서명·공증 dmg(Apple Developer), 상표·도메인 확정, 영어 랜딩.
- 새 관심사 모드는 확장 원칙을 따른다. identity 문서의 "누구를 위한 것인가"를
  먼저 고친 뒤 기능을 만든다.
