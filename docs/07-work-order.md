# Movie Desk 실행 작업 순서

작성 2026-09-02 · 제품 가드레일 [`../CLAUDE.md`](../CLAUDE.md) · 정체성
[`00-identity.md`](00-identity.md) · 마스터플랜 [`06-master-plan.md`](06-master-plan.md)

이 문서는 마스터플랜을 실제 구현 배치로 바꾼 실행 대기열이다. 위에서 아래 순서로
진행하며, 앞 배치의 완료 게이트가 닫히기 전에는 의존하는 다음 배치를 시작하지 않는다.
실제 촬영본에서 데이터 손실이나 완주 차단 문제가 발견되면 해당 문제를 최우선으로
올릴 수 있다.

## 모든 배치의 공통 완료 기준

- 라이브러리·전문 편집·안내와 보조 중 어떤 축을 개선하는지 커밋이나 문서에 적는다.
- 기존 프로젝트와 원본을 훼손하지 않으며, 데이터 구조 변경에는 마이그레이션 테스트가
  있다.
- 기본 경로와 정밀 경로를 함께 확인한다. 쉬운 UI를 위해 전문 제어를 제거하지 않는다.
- 빈 상태, 정상 상태, 오류 상태, 키보드 조작을 해당 범위에서 확인한다.
- 변경 위험에 맞는 단위·통합·브라우저 테스트를 추가하고 관련 품질 명령을 통과한다.
- UI 변경은 Photo Desk 디자인 언어와 1024px·1440px 화면을 확인한다.
- 구현, 테스트, 문서, 검증 결과를 가능한 한 하나의 독립 커밋으로 남긴다.

## A. 현재 제품을 안전한 기준선으로 만들기

### W00 — CI와 보안 기준선 복구

목적: 이후 실패가 새 변경 때문인지 즉시 구분할 수 있는 녹색 기준선을 만든다.

1. OSV가 보고한 `postcss`와 `nanoid` 취약 버전을 호환 가능한 수정 버전으로 갱신한다.
2. 잠금 파일을 갱신하고 직접·전이 의존성의 실제 해소 여부를 확인한다.
3. knip 미사용 export/type 10건과 포맷 차이를 동작 변경과 분리해 정리한다.
4. 로컬과 GitHub CI가 같은 명령을 사용하도록 확인한다.

완료 게이트:

```bash
pnpm lint
pnpm typecheck
pnpm test
pnpm audit:prod
pnpm build
pnpm test:e2e
```

모두 통과하고 작업 트리가 의도한 변경만 포함한다.

### W01 — 버전·저장 형식·호환 정책 고정

목적: 리팩터링과 릴리스가 기존 사용자 데이터를 깨뜨리지 않게 한다.

1. 루트·web·core·desktop 버전의 역할과 릴리스 버전 단일 기준을 정한다.
2. 프로젝트 JSON, IndexedDB, OPFS, 데스크톱 origin의 현재 버전을 기록한다.
3. 이름 변경 전 `cut_editor` 데이터와 현재 Movie Desk 데이터의 열기 테스트를 고정한다.
4. 앞으로 데이터 구조가 바뀔 때 사용할 마이그레이션 규칙과 실패 시 복구 방식을 적는다.

완료 게이트: 과거 fixture를 현재 앱에서 열고 저장한 뒤 다시 열 수 있으며, 실패한
마이그레이션이 원본 데이터를 덮어쓰지 않는다.

### W02 — 재현 가능한 전체 여정 검증 장치

목적: 개별 기능이 아니라 한 편을 완성하는 흐름을 계속 검사한다.

1. 저장소에 커밋 가능한 소형 영상·사진·오디오 fixture를 만든다.
2. 가져오기 → 라이브러리 확인 → 수동 타임라인 편집 → 선택형 초안 → 실행취소 →
   저장·복원 → 내보내기 흐름을 E2E로 묶는다.
3. 가져오기 시간, 첫 재생 시간, 탐색 응답, 초안 시간, 내보내기 시간을 기록할 측정
   틀을 만든다.

완료 게이트: 같은 fixture와 명령으로 전체 흐름과 성능 기준선을 반복 측정할 수 있다.

## B. 첫 안정판으로 실제 영상 한 편 완주하기

### W03 — `v0.4.0-rc.1` 설치본 만들기

목적: 브라우저 개발 환경이 아닌 실제 macOS 설치본으로 이후 작업을 검증한다.

- arm64/x64 DMG, 앱 이름·아이콘·설치 배경, 첫 실행, 업데이트 확인을 검증한다.
- Whisper와 FaceLandmarker 등 선택형 모델의 포함·다운로드 상태를 정확히 안내한다.
- 인터넷이 없는 상태에서 가능한 기능과 최초 다운로드가 필요한 기능을 구분한다.

완료 게이트: 두 아키텍처의 RC가 실행되고 기존 프로젝트를 열며, 미디어가 외부로
업로드되지 않는다.

### W04 — 실제 촬영본 도그푸딩 1회차

목적: 추측이 아니라 실제 사용에서 다음 P0/P1 순서를 결정한다.

- 가족·여행 촬영본 50~200개를 사용한다. MP4, MOV, HEVC, HEIC, 세로 영상, 사진,
  음악을 섞되 개인 원본은 저장소에 커밋하지 않는다.
- 가져오기 → 정리·검색 → 수동 편집 또는 안내형 초안 → 정밀 마무리 → 내보내기 →
  실제 기기 재생까지 수행한다.
- `docs/dogfood/YYYY-MM-DD.md`에 실패, 대기 시간, 이해하지 못한 UI, 다른 앱을 찾은
  순간을 기록한다.

완료 게이트: 결과물 한 편과 측정 기록이 남고, 문제를 P0·P1·P2로 분류한다.

### W05 — 원본 호환성과 라이브러리 입구 닫기

목적: 사용자가 변환 도구를 먼저 찾지 않게 한다.

- W04에서 확인된 P0/P1을 우선하고 HEIC/HEIF, HEVC, MOV, 회전 메타데이터,
  Live Photo, DCIM 폴더를 처리한다.
- 실패 파일 하나가 전체 가져오기를 중단하지 않게 하고 파일별 원인·해결·재시도를
  제공한다.
- 촬영 시각·위치·방향을 보존하고 지원 여부를 자동 테스트와 호환표로 고정한다.

완료 게이트: 기준 촬영본이 전부 들어오거나 각 파일에 실행 가능한 해결 안내가 나온다.

### W06 — 현재 편집·보조·출력 흐름 완성

목적: 이미 구현된 기능을 데모가 아니라 실제 결과물을 만드는 수준으로 묶는다.

- 타임라인 마무리, 제목·한글 자막, 음악, 화면비, 음량, 내보내기의 P0/P1을 해결한다.
- 선택형 자동 초안은 선택·탈락 이유, 꼭 포함·제외, 한 번에 실행취소를 보장한다.
- 메신저, YouTube, TV·태블릿용 결과를 실제 재생기로 검증한다.
- 손상 프로젝트, 누락 미디어, 저장 공간 부족, 내보내기 중단의 복구 경로를 확인한다.

완료 게이트: 서로 다른 실제 촬영본 두 세트가 다른 편집기 없이 끝까지 완주하고
알려진 데이터 손실 또는 완주 차단 문제가 없다.

### W07 — 첫 안정판 `v0.4.0`

목적: 현재 제품의 완주 가능한 기준선을 배포 가능한 상태로 고정한다.

- 전체 CI, 전체 여정 E2E, arm64/x64 설치 체크리스트를 통과한다.
- `mp4-muxer` 교체가 출력 안정성에 필요하면 이 단계 전에 완료한다.
- 알려진 제한과 모델 다운로드 조건을 릴리스 노트에 정직하게 적는다.

완료 게이트: `v0.4.0` 태그와 Movie Desk 이름의 설치본을 만들고 재현 가능한 검증
결과를 남긴다.

## C. 세 핵심 축을 제품 수준으로 키우기

### W08 — 영상 자산 소유권과 라이브러리 데이터 모델

목적: 프로젝트별 미디어 빈을 장기적인 영상 라이브러리로 확장할 기반을 만든다.

- 참조형·복사형·관리형 미디어의 의미와 원본 소유권을 정의한다.
- 전역 자산과 프로젝트 사용 정보, 컬렉션·태그·평점·즐겨찾기·메타데이터를 분리한다.
- 중복, 누락, 재연결, 프록시, 휴지통의 상태 모델과 마이그레이션을 설계한다.

완료 게이트: 같은 자산을 복제하지 않고 여러 프로젝트에서 사용할 수 있고, 어떤
명령도 원본을 묵시적으로 이동·삭제·덮어쓰지 않는다.

### W09 — 라이브러리 작업대

목적: 수백~수천 개 영상을 편집 전에 실제로 찾고 정리할 수 있게 한다.

- 빠른 복합 검색, 필터, 정렬, 컬렉션, 태그, 평점, 즐겨찾기, 사용 여부를 제공한다.
- 코덱·프레임률·카메라·렌즈·촬영일·장소 메타데이터를 인덱싱한다.
- 중복·유사 장면 검토, 누락 재연결, 프록시 상태, 안전한 삭제·복원을 UI로 연결한다.

완료 게이트: 혼합 자산 1,000개 이상에서 정리·검색·일괄 작업의 정확도와 응답 시간을
측정하고, 새 사용자가 다음 행동을 이해한다.

### W10 — 재생·프록시·분석 성능 기반

목적: 전문 편집 기능을 올려도 버틸 수 있는 공통 미디어 파이프라인을 만든다.

- 재생·장면 감지·모션 추적이 가능한 범위에서 WebCodecs 디코더와 캐시를 공유한다.
- 4K, 긴 영상, 다중 트랙의 병목을 계측하고 프록시·워커·GPU 경계를 수치로 결정한다.
- 작업 진행률·취소·재개와 메모리·GPU 자원 해제를 검증한다.

완료 게이트: 고정 fixture에서 목표 프레임 유지율과 분석 시간 기준을 문서화하고
회귀 테스트로 지킨다.

### W11 — 전문 타임라인의 정밀도

목적: 숙련 사용자가 다른 편집기로 이동하게 만드는 조작 공백을 제거한다.

- 프레임·타임코드·수치 입력, 정밀 트림, 일관된 키프레임 편집을 완성한다.
- 피치 보존 속도 변경, 중첩 시퀀스, 멀티캠 등 실제 작업 빈도와 의존성 순서로
  기능을 추가한다.
- 키보드 중심 편집, 선택 모델, 실행취소, 긴 히스토리의 신뢰성을 검증한다.

완료 게이트: 정해진 전문 편집 과제를 마우스·키보드 양쪽으로 정확히 재현하고,
저장·복원 뒤 결과와 타이밍이 동일하다.

### W12 — 전문 마무리와 전달

목적: 영상·색·음향·자막·출력을 한 프로그램에서 끝낸다.

- 컬러 관리·스코프·LUT, 오디오 미터·버스·믹싱, 제목·자막의 핵심 공백을 메운다.
- 해상도·프레임률·색 공간·오디오 구성별 내보내기 품질과 동기화를 검증한다.
- 백그라운드 렌더와 고급 코덱은 실측 병목과 실제 전달 요구에 따라 도입한다.

완료 게이트: 대표 결과물을 별도 편집·색보정·오디오 도구 없이 납품 가능한 파일로
완성한다.

### W13 — 안내와 단계적 공개 통합 점검

목적: 앞 단계에서 만든 전문 기능을 숨기지 않으면서 처음 사용자도 완주하게 한다.

- 새 프로젝트, 라이브러리, 편집, 마무리, 오류 복구의 다음 행동을 맥락에 맞게 안내한다.
- 기본 조작에서 정밀 조작까지 같은 화면에서 자연스럽게 깊어지게 한다.
- 별도의 장난감 모드나 기능을 가리는 초보자 모드는 만들지 않는다.

이 작업은 W08~W12의 마지막에 한 번 붙이는 UI 작업이 아니다. 각 배치에서 안내를
함께 구현하고, W13에서 전체 일관성과 학습 곡선을 검증한다.

완료 게이트: 처음 쓰는 사용자가 설명 없이 짧은 영상을 완성하고, 숙련 사용자가 같은
프로젝트를 이어받아 정밀하게 마무리한다.

### W14 — 로컬 AI 보조의 제품화

목적: AI를 제품의 주인공이 아니라 라이브러리와 편집 결정을 빠르게 하는 도구로 만든다.

- 의미 검색, 전사·자막, 문제 장면 표시, 유사 장면, 선택형 추천과 초안을 공통 분석
  데이터 위에 올린다.
- 모델 다운로드·용량·진행률·삭제·오프라인 상태를 사용자가 통제하게 한다.
- 중요한 추천에는 이유가 있고, 적용 전 미리 볼 수 있으며, 한 번에 되돌릴 수 있게 한다.

완료 게이트: AI를 전혀 사용하지 않아도 전체 작업이 가능하고, 사용할 때는 측정 가능한
시간 절감 또는 탐색 개선이 있다.

## D. 규모 검증과 공개 준비

### W15 — 대규모·장기 프로젝트 검증

- 혼합 자산 1,000개 이상, 긴 타임라인, 여러 프로젝트 재사용, 앱 재시작과 복구를
  포함한 장기 테스트를 수행한다.
- 메모리, 저장 공간, 검색 응답, 첫 프레임, 탐색, 저장, 내보내기 시간을 기록한다.
- 데이터 손실, 무응답, 원본 훼손, 다른 편집기로 이동해야 하는 핵심 공백을 0으로 만든다.

### W16 — 공개·상용화 준비

- 처음 쓰는 사람과 숙련 사용자 모두를 대상으로 과제형 사용성 검증을 진행한다.
- 서명·공증, 개인정보·오픈소스 고지, 업데이트와 롤백을 준비한다.
- 공개 상용화 전에 한국과 목표 시장의 상표를 조사하고 필요하면 제품명을 교체한다.
